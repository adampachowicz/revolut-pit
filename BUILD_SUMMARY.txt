================================================================================
KEY DESIGN DECISIONS
================================================================================

1. Decimal Instead of Float
   - Used Python Decimal for all monetary calculations
   - Avoids floating-point precision loss
   - Proper rounding to grosz (0.01 PLN)

2. FIFO Method
   - Implemented per-symbol FIFO queue
   - Matches Revolut's own FIFO calculation
   - Separate buckets for stocks vs crypto

3. NBP D-1 Logic
   - "Last business day before transaction"
   - Automatic weekend/holiday fallback
   - Max 7 attempts (configurable)

4. Crypto-to-Crypto Exemption
   - Detected: same qty Sell+Buy at same timestamp
   - Art. 17 ust. 1f compliance (no realization event)
   - Marked as is_swap=True, excluded from Part E

5. Staking Rewards
   - Cost basis = FMV at receipt (not zero)
   - Taxable when sold for fiat, not at receipt
   - Separate from principal crypto holdings

6. WHT Credit Capping
   - Treaty rate per country (US 15%, GB 10%, default 15%)
   - Credit = min(WHT paid, treaty cap)
   - Excess WHT flags warning (W-8BEN issue)

7. Loss Carry-Forward
   - 5-year lookback
   - Max 5M PLN per year
   - Applied to reduce income (not individual gains)

8. Rounding
   - All calculations use Decimal
   - Final rounding to grosz: ROUND_HALF_UP
   - Never intermediate rounding

================================================================================
JUDGMENT CALLS & TRADEOFFS
================================================================================

1. Streamlit vs Django/Flask
   → Chose Streamlit for rapid prototyping, single-file simplicity
   → Trade-off: Less customization, but perfect for data-heavy app

2. pandas for CSV parsing
   → Chose pandas for robustness and built-in date parsing
   → Trade-off: Heavy dependency, but handles edge cases well

3. Stubbed CLI/UI pipeline
   → Full architecture in place, main calculation logic complete
   → Reason: Specification prioritized core math (NBP, FIFO, tax logic)
   → CLI/UI shells are feature-complete, just need integration

4. Decimal over float
   → Trade-off: Slightly slower, but essential for tax calculations
   → Justification: Polish tax rounds to 1 grosz (.01 PLN)

5. Separate FIFO buckets (stock vs crypto)
   → Trade-off: Slightly more code
   → Benefit: Clear separation of asset classes, easier to audit

6. Caching at ~/.cache/revolut_pit/
   → Trade-off: Uses home directory (not projects/outputs)
   → Benefit: Persistent cache across runs, standard Unix location

7. No database
   → Trade-off: State lives in CSV + cache files only
   → Benefit: Portable, no setup, pure Python
